# Sublarr V1.6 — Release Design

**Date:** 2026-07-03
**Status:** Design approved (headline), pending spec review
**Scope:** 7 independent features shipped as one 1.6.0 release

> Derived from the 2026-07-02 gap analysis vs Bazarr/Bazarr+/Lingarr/Subgen
> and the 2026-07-03 Bazarr+ v2.4.0 "Prism" deep-dive synthesis.
> Two Prism features are **explicitly out of scope**: the Distribution Hub
> (multi-tenant subtitle-serving API + Jellyfin plugin) and the curated
> Provider Hub supply-chain apparatus — wrong audience / wrong strategic
> direction for a solo self-hosted tool.

## Release contents

| # | Feature | Size | Role |
|---|---------|------|------|
| 1 | Combined / bilingual subtitles | M | Headline |
| 2 | Manual subtitle upload | S–M | Daily-use gap vs Bazarr |
| 3 | Reverse-proxy header auth | S | Security |
| 4 | Side-by-side sync-compare modal | S | Trust/UX |
| 5 | What's-New wizard | S | UX |
| 6 | API-key encryption-at-rest | S–M | Security |
| 7 | Editor fullscreen toggle | XS | UX polish |

## Build sequencing

Ordered by dependency + risk. Each feature ships as its own atomic commits;
the release goes out when all are green.

1. **Security foundation first** — #6 Key-encryption + #3 Header-auth.
   Independent, security-critical, best done carefully and early.
2. **#2 Manual upload** — hardens the sidecar-write path that the headline
   feature reuses.
3. **#1 Combined subtitles** (headline) — largest; benefits from a solid
   upload/sidecar path; couples to the translation stack.
4. **#4 Sync-compare** — FE-heavy, independent.
5. **#5 What's-New wizard + #7 Editor fullscreen** — small FE polish, last.

**Release-timing note:** the two security items (#6, #3) are built first and
are fully independent of the headline. Default is to bundle all seven into
1.6.0 (per user instruction). Because they are built first, they can be split
into a faster 1.5.x point release with zero rework if desired later.

## Feature 1 — Combined / Bilingual Subtitles (Headline)

### Purpose & use case
Compose two per-language sidecars (typically DE + EN) into one **combined
subtitle file** so anime / language-learner users can read both languages at
once. Sublarr's edge over Bazarr+: if one language is missing, it can be
generated **on demand** via the translation stack — Prism's combine is
composition-only and never translates.

### Data model (extend `LanguageProfile`, no new config table)
`LanguageProfile` already carries multiple target languages
(`target_languages_json`), `hi_preference`, `forced_preference`, and
per-series/movie overrides. Add combine rules there:

| Column | Type / default | Meaning |
|--------|----------------|---------|
| `combine_enabled` | int, default `0` | automatic combine for this profile |
| `combine_format` | text, default `"ass"` | `"ass"` \| `"srt"` |
| `combine_languages_json` | text, default `"[]"` | 2–3 target langs to combine (subset of `target_languages_json`) |
| `combine_position_json` | text, default `'{"primary":"bottom","secondary":"top"}'` | ASS positioning only; **primary = first entry in `combine_languages_json`** (e.g. DE bottom), secondary = second (EN top) |

An Alembic migration adds the columns additively (nullable / defaults →
contract-safe for the frontend, no breaking response-shape change).

### Combined output = managed, editable subtitle row
The combined file is a **first-class managed subtitle row** (not a loose
file) so it is editable in the existing editor and re-combinable (Prism
parity). **No descope** — full quality per user direction.

Sidecar naming follows the existing convention:
`<stem>.<lang1>-<lang2>.combined.ass` (e.g. `Movie.de-en.combined.ass`).

### Trigger model
1. **Automatic (per-profile):** after download/extract, when both target
   languages exist as sidecars → compose. If one is missing → **silently
   skip** (never triggers translation).
2. **On-demand (button):** "Combine" action at episode/movie level. If a
   language is missing, a "**Translate & combine**" action appears →
   generates the missing language via the translation stack (with the
   existing quality gate), then composes. Runs through the existing queue
   with explicit app-context (see `feedback_flask_app_context_in_threads`).

### Composition engine (adopted from Prism's design)
- **Index-based alignment detector:** sibling (equal cue count) / offset /
  overlap.
- **ASS:** positioning via style / `\an` tags — primary bottom, secondary
  top (configurable per profile).
- **SRT:** stacked lines under a shared timestamp.
- **Source priority per language:** `plain > hi > forced`.
- Runs `subtitle_sanitizer` (ASS Lua strip, SRT/VTT HTML sanitize) on both
  inputs before composing.
- **Bitmap-codec sources (PGS/VobSub) rejected** (same rule as the embedded
  extractor).

### API (`/api/v1/`)
- `POST /episodes/<id>/subtitles/combine`
- `POST /movies/<id>/subtitles/combine`
  Body: `{ languages: [..], format: "ass"|"srt", translate_missing: bool }`
- Batch variant for list pages (mass-combine), mirroring Prism.
- All endpoints require `is_safe_path` on any resolved output path.

### Frontend
- Combine action in the **EpisodeMenu** (folge-übergreifend) — respects the
  Episode-vs-Pill action split (`feedback_episode_pill_action_split`).
- Combine rules in the `LanguageProfile` editor: toggle + format + language
  selection + position.
- Combined file opens in the existing editor (stacked cues per timestamp).
- Tailwind-first styling per the adopted 2026-04-18 styling policy.

### Error handling
- Missing source language without `translate_missing` → silent skip (not an
  error).
- Translation fails the quality gate → no combine, clear error, **no partial
  artifact left on disk**.
- Bitmap-codec source → rejected with a clear message.

### Testing
- Unit: alignment detector (sibling/offset/overlap), ASS positioning, SRT
  stacking, source priority.
- Integration: combine endpoints (both present / one missing + translate /
  quality-gate fail).
- Contract: new profile fields are additive → the React frontend does not
  break (per `flask-react-api-contracts`).

## Feature 2 — Manual Subtitle Upload

### Backend
- `POST /api/v1/episodes/<id>/subtitles/upload` and
  `POST /api/v1/movies/<id>/subtitles/upload` (multipart).
- Full security chain: `is_safe_path` (destination), `subtitle_sanitizer`
  (ASS Lua strip / SRT-VTT HTML), `archive_utils` if a `.zip` is uploaded
  (bomb/slip guards — caps already 20 MB archive / 50 MB extracted / 100:1),
  **magic-byte / format validation**, size cap. Bitmap codecs rejected.
- Naming/model: sidecar per `services.embedded_extractor` convention; creates
  a managed subtitle row (`source="manual"`), appears in history. Dedupe
  against an existing sidecar → overwrite prompt.

### Frontend
- Drag-&-drop + file picker in the EpisodeMenu.
- Dialog: language + HI/forced flags + overwrite behavior.
- Accepts `.srt / .ass / .ssa / .vtt / .sub`.

### Testing
- Reject path traversal, oversized files, bitmap codecs, malformed content.
- Accept + sanitize valid uploads; correct sidecar naming; overwrite flow.

## Feature 3 — Reverse-Proxy Header Auth

### Backend (`auth.py`)
- Trust `Remote-User` / `X-Forwarded-User` **only** when the direct peer IP
  is in a trusted-proxy allowlist (spoofing protection). Runs alongside
  existing session / API-key auth.

### Config (UISettings → DB `config_entries` — NO new env vars)
Configured entirely in the **Settings menu** (Settings → System / Security),
persisted in `config_entries`, read per-request in `auth.py`. No BootSettings
/ env fields (would hit `lint_no_new_env_fields.py`). Per
`feedback_env_vars_minimum_ui_first`.
- `proxy_auth_enabled` (bool, default **false**)
- `proxy_auth_trusted_ips` (list of CIDR, default `[]`) — header honored only
  if the direct peer IP matches one of these
- `proxy_auth_header` (text, default `Remote-User`)

### Goal
Authelia / authentik SSO; closes the "prod reachable without login" flank via
the existing reverse proxy. Makes OIDC/2FA unnecessary for the target
audience.

### Testing
- Spoofed header from an untrusted IP → rejected.
- Trusted IP + header → authenticated.
- Disabled (default) → header ignored entirely.

## Feature 4 — Side-by-Side Sync-Compare Modal

### Backend
- Sync run retains candidate outputs per engine (ffsubsync / alass).
- Endpoint returns comparison data + an "apply chosen" action.
- Explicit failure surface when no engine produced output (Sublarr already
  has sync metrics / engine-failure data).

### Frontend
- `SyncOutputCompareModal`: original vs synced (or engine A/B) side by side,
  cue diff, choose which to keep. Reuse the editor diff / waveform
  components.

### Testing
- Compare data shape; apply-chosen persists the right file; no-output failure
  surfaces clearly.

## Feature 6 — API-Key Encryption-at-Rest (Security)

### Current state (verified 2026-07-03)
Provider API keys are stored **plaintext** in `config_entries` — no Fernet /
AES / encrypt primitive anywhere in the backend, only UI masking.

### Design
- **Crypto:** Fernet (`cryptography`, new dependency → add to
  `docs/THIRD-PARTY-LICENSES.md` in the same commit) for values flagged
  *sensitive*. Sensitivity is decided by a **suffix classifier** —
  keys/fields ending in `_api_key`, `_password`, `_token`, `_secret` plus the
  exact key `api_key` — with an **exclusion set** (`ui_session_secret` = the
  master-key source, must stay plaintext; `ui_password_hash` = already
  bcrypt). Future provider keys are auto-covered.
- **Scope covers two stores:** (1) sensitive `config_entries` values via
  `ConfigRepository`; (2) `ProviderAccountPool.api_key` / `.password`
  (core.py:534-538, already flagged "encryption-at-rest is a future task").
- **Ciphertext format:** version-prefixed `enc:v1:<fernet-token>` so plaintext
  and ciphertext coexist during migration and `decrypt()` is idempotent
  (returns unprefixed input unchanged).
- **Key management (NO new env var):** auto-generated master key stored as a
  key file at `{config_dir}/.encryption_key` (default `/config/.encryption_key`)
  with `0600` perms, generated on first use. The master key is an internal
  generated secret — **not** a user-facing setting, so nothing to expose in
  the Settings menu; it "just works" on first boot. Rotation documented as an
  ops step.
  - **Do NOT derive the key from the existing app secret.** Sublarr's Flask
    `SECRET_KEY` comes from `ui_session_secret`, which is stored **inside the
    DB** (`config_entries`, see `ui_auth.py:_get_or_create_secret_key`).
    Deriving the encryption key from it would co-locate key and ciphertext in
    the same table — a DB dump would leak both and the encryption would be
    worthless. The master key MUST live in a **separate file outside the DB**.
  - **Backup interaction (must handle):** the key file is separate from
    `/config/sublarr.db` and outside `/config/backups`. `backup_full.py` must
    include `.encryption_key` in backups, otherwise a restore leaves encrypted
    values permanently unrecoverable. This means a leaked backup exposes key +
    ciphertext together — backups are therefore treated as **trusted
    storage**.
  - **Threat-model note (be honest):** this protects against **DB-only
    leakage** — a shared/leaked `sublarr.db`, a SQL-injection read of
    `config_entries`, or an accidentally committed database — but **not**
    against full `/config` filesystem compromise or a leaked full backup
    (both hold key + ciphertext). That is the realistic, meaningful
    improvement over today's plaintext for a self-hosted tool.
- **Migration:** encrypt existing plaintext values in `config_entries`;
  transparent decrypt in the config layer; UI still masks.

### Testing
- Round-trip encrypt/decrypt; migration of existing plaintext; missing-key
  handling; key rotation.

## Feature 7 — Editor Fullscreen Toggle

- FE-only toggle (`f` / `Esc`) in the editor; subtitle overlay retained.
- Additive only — **respects the waveform gold-standard**
  (`project_waveform_gold_standard`), touches no locked surfaces.

### Testing
- Toggle enters/exits fullscreen; overlay persists; no regression to locked
  editor surfaces.

## Out of scope (explicitly declined)

- **Distribution Hub + Jellyfin plugin** — multi-tenant subtitle-serving API
  is the wrong audience for a single-user self-hosted tool; L-effort with a
  permanent C#/Jellyfin maintenance burden; expands inbound attack surface,
  contrary to Sublarr's hardening direction.
- **Provider Hub curated catalog / venv isolation / trust labels /
  built-in-replacement shadow-swap** — infrastructure for a community-driven
  plugin ecosystem Sublarr does not have; the "replace built-in" capability
  is exactly the supply-chain vector on Sublarr's open threat-model roadmap
  (P1). The git-URL marketplace with HTTPS + domain allowlist is sufficient.
- **Archive bomb-cap hardening** — already stricter in Sublarr (20/50 MB,
  100:1) than Prism (32/16/64 MB). No action.

### Independently adoptable later (not 1.6)
- **OpenSubtitles.org native adapter** (Cloudflare/PoW solving, no API key) —
  the one genuinely valuable piece of the Provider Hub, buildable as a single
  provider adapter without the catalog apparatus. Track as a standalone
  provider ticket.
