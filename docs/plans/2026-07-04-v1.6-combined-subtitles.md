# V1.6 Feature #1 — Combined / Bilingual Subtitles (Headline)

**Started:** 2026-07-04 · **Spec:** `docs/specs/2026-07-03-v1.6-release-design.md` (Feature 1)
**Base:** master @ `0a7a9b52` (after #8 provisional-MT phase 1)

Compose two per-language sidecars (typ. DE+EN) into one combined subtitle file.
Edge over Bazarr+/Prism: if one language is missing it can be generated on demand
via the translation stack (Prism is composition-only).

## Build order (atomic commits, TDD)

**Progress:** C1 `ea822cf8` · C2 `36645946` · C3 `c70f68b7` — all green.

- [x] **C2 — Composition engine** `services/subtitle_combine.py` (pure, no

  ASS overlay (primary bottom `\an2` / secondary top `\an8`, configurable),
  SRT stacking (shared timestamp), source priority (plain > hi > forced),
  sanitize inputs, reject bitmap. Comprehensive unit tests.
- [x] **C3 — API** `POST /library/{episodes,movies}/<id>/subtitles/combine`
  + batch. Body `{languages, format, translate_missing}`. Resolve sidecar per
  language by priority; both present → combine now; missing + translate_missing
  → enqueue via translation stack (app-context) then combine; missing w/o flag
  → silent skip (automatic) / clear 422 (on-demand). `is_safe_path` on output,
  atomic write, managed subtitle row `source="combined"`. Automatic per-profile
  hook after download/extract. Integration tests.

## Naming / contracts
- Sidecar: `<stem>.<lang1>-<lang2>.combined.<fmt>` (e.g. `Movie.de-en.combined.ass`).
- Managed row: `source="combined"` (new source value alongside provider/manual/
  embedded/machine_translation).
- Position → ASS `\an`: bottom=2, top=8, middle=5.
